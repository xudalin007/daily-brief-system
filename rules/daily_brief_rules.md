# 每日简报正式规则（Source of Truth）

- 版本：v1.1
- 基线日期：2026-07-31
- 最近正式更新：2026-08-02
- 状态：当前唯一有效规则
- 优先级：若历史聊天、旧提示词、README、checkpoint、changelog历史或旧日报与本文件冲突，以本文件最新版为准。
- 维护规则：用户说“固定方案 / 固定一下 / 就按这个方案”时，视为需要更新本规则，并同步追加 CHANGELOG。

## 日报总体架构与通用原则

每日简报是用于支持观察与决策的中文研究简报，不是简单新闻堆砌，也不是单纯指标列表。

正式采用三层结构：

1. **总览层**：通过“0｜今日30秒结论”快速说明今天发生了什么、主要机会与主要风险。
2. **证据层**：通过“1｜人工智能与科技”“2｜BTC与加密市场”“3｜宏观经济与投资”“4｜国内外重大新闻”展示可核查事实、数据、来源、传导路径与不确定性。
3. **结论层**：通过“5｜今日5点总结”形成可执行的观察结论。

日报固定输出顺序：

0. 今日30秒结论
1. 人工智能与科技
2. BTC与加密市场
3. 宏观经济与投资
4. 国内外重大新闻
5. 今日5点总结

通用要求：

- 日报事件扫描以生成截止时点前24小时内的新进展和实质更新为核心；AI板块另设7天重大事件补漏机制。
- 历史背景可用于解释当前新变化，但不得把旧事件重新包装成当天新闻。
- 日线指标、最近完整交易日数据和30D/90D/365D历史比较不受新闻24小时时窗限制，但必须标注实际数据日期与数据质量。
- 所有新鲜数据优先使用可靠、可验证来源，并标注日期或时间。无法可靠取得时，明确写“未取得可靠值”，不得猜测，不得沿用旧值、估算值或0冒充当天可靠值。
- 明确区分事实、分析与推测。分析必须能追溯到前文事实或数据；推测和待验证信息必须显式标记。
- 有明确增量价值时，可以提供可直接使用的工具与机会；不得为了填充版面推荐未经验证或与当天主题无关的内容。
- “更全面”不等于“更长”。优先采用表格、事件聚类、跨板块去重和重点展开，降低阅读成本。
- 版式和完成度应达到完整研究报告水平；数据可靠性、日期一致性、指标口径和来源验证必须高于普通新闻简报。

## 0｜今日30秒结论

日报开头固定提供：

- 今日最重要的一句话；
- BTC总灯号；
- AI总灯号；
- 宏观总灯号；
- 能源、地缘或其他确有必要的总灯号，不为凑表强制增加。

“今日最重要的一句话”应同时压缩当天最重要的变化、当前主要机会与当前主要风险。总灯号必须由后文证据层支持，不得依据单一标题或单一指标机械生成。

总灯号使用表格展示：

| 领域 | 总灯号 | 一句话判断 |
|---|---|---|
| BTC | ... | ... |
| AI | ... | ... |
| 宏观 | ... | ... |
| 能源 / 地缘（必要时） | ... | ... |

总灯号表格正下方、进入“1｜人工智能与科技”之前，固定显示：

> 灯号说明：🟢有利｜🟡中性/待确认｜🟠风险升高｜🔴高风险/明显不利｜⚪数据不足、暂不判断。

灯号正式定义：

- 🟢 绿灯：环境或信号总体有利。
- 🟡 黄灯：中性、多空交织或需要进一步确认。
- 🟠 橙灯：风险明显升高，应提高警惕。
- 🔴 红灯：高风险或明显不利。
- ⚪ 灰灯：数据不足，暂时无法可靠判断。

“偏绿 / 偏橙”只表示当前主灯号等级内部的方向倾斜，不得改变主灯号等级。例如，“🟡黄灯偏绿”和“🟡黄灯偏橙”仍然都属于黄灯。⚪灰灯不得解释为看空，只代表无法可靠判断。

## 1｜人工智能与科技

### 1.1 双时间窗

正式采用：

- **24小时核心扫描**：筛选生成截止时点前24小时内真正重要的新进展。
- **7天重大事件补漏**：只补充过去7天内仍持续影响当前判断、但此前可能遗漏的重大模型、产品、价格、监管或产业事件。

7天窗口不是“本周新闻大全”。补漏内容必须明确标记为“7天重大事件补漏”，说明原始发生日期以及为什么今天仍重要；不得伪装成当天新事件，也不得重复此前已经充分报道的内容。

### 1.2 AI来源优先级与证据标准

固定来源等级：

1. **Level 1：公司、政府或项目官方一级源**。例如OpenAI、Anthropic、Google DeepMind、DeepSeek、Microsoft、Amazon、NVIDIA、欧盟委员会及其他政府监管机构的公告、文件、产品说明或原始发布。
2. **Level 2：高质量主流媒体**。例如Reuters、Financial Times、Bloomberg、财新等。
3. **Level 3：专业科技媒体**。
4. **Level 4：中文门户、搜索摘要、聚合新闻和转载**。

高影响事件和爆炸性标题必须尽量获得Level 1或可靠Level 2来源验证。无法验证时，只能明确标记“待验证”，或者不把它写成正式日报事实。Level 4只可作为发现线索，不得单独支撑高影响事实；不得因为标题足够吸引人而降低证据标准。

### 1.3 事件聚类、去重与每日数量

AI板块按“事件 / 主题”聚类，不按新闻文章数量逐条罗列。同一底层事件的多来源报道合并处理；多个公司或数据如果回答同一个产业问题，也应合并为一个主题。

例如，Microsoft Azure增长、Amazon AWS增长与韩国半导体或电脑出口增长，可以合并为“AI真实需求与ROI得到财务和实体贸易数据验证”，而不是拆成三条新闻。

原则上每天输出4～5个高价值主题，不要求强行达到5个；不足4个高质量主题时宁缺毋滥。优先级依次为：

1. 能力边界突破；
2. 成本或价格变化；
3. Agent、安全或监管；
4. 商业需求与ROI；
5. 重大产品与应用落地。

第二梯队产品更新可以保留，但不得挤占更重要主题。

### 1.4 AI主题写法

每个高价值主题尽量回答：

1. **事实**：发生了什么？
2. **为什么重要**：这件事改变了什么？
3. **产业 / 投资影响**：它可能影响哪个环节？

事实、分析、推测或待验证内容必须明确区分。不得把分析性观点包装成已经确认的事实，也不得把可能性写成确定结果。

## 2｜BTC与加密市场

### 2.1 BTC核心指标仪表盘

本板块首先固定给出“BTC核心指标仪表盘”，完整展示核心指标，即使某项为Unavailable也保留该行。

建议字段：

| 维度 | 指标 | 最新值 | 变化/趋势 | 信号 | 数据日期 | 数据质量 |
|---|---|---:|---|---|---|---|

数据质量统一采用：

- **Verified（已验证）**：数据源、日期和口径均可靠确认。
- **Delayed（有延迟）**：数据可靠，但存在已知时间延迟；必须显示实际数据日期。
- **Provisional（暂报）**：当前数据尚未完全确认或当日尚未final；不得把暂报值冒充正式最终值。
- **Unavailable（不可用）**：未取得可靠值。

不得用0、旧值或估算值伪装成Unavailable指标的当前值。统一数据质量状态用于日报展示，不能覆盖底层指标自身的完整性状态；例如ETF的`complete / provisional / unavailable`和各Funding provider的`available / unavailable`仍须保留。

### 2.2 BTC正文展开与指标去重

仪表盘负责完整展示核心指标；正文原则上只重点展开当天变化最大、最值得解释、对判断有增量价值的约3～4项。连续多日没有实质变化的核心指标无需每天重复长篇解释，但不得因此从仪表盘消失。

继续使用以下核心体系：

- MVRV Ratio；
- STH-MVRV；
- AHR999；
- US Spot BTC ETF Flow；
- Funding；
- aSOPR；
- SSR Oscillator；
- CVDD dual-track；
- 必要的宏观联动。

每个指标应回答不同问题，不得为了显得全面而加入大量高度重复指标。Fear & Greed、BTC Dominance、GMA200目前不得自动成为固定核心指标；只有后续正式证明有明显增量价值时，才能升级。

### 2.3 禁止代用指标冒充正式指标

正式指标未取得可靠值时，必须写“未取得可靠值”，不得使用相关指标、代理指标或自建估算冒充。

明确示例：

- Long-Short Diff ≠ STH-MVRV；
- Network Profit/Loss ≠ aSOPR；
- 其他相关链上指标也不得借用正式指标名称解释。

相关指标可以作为辅助指标，但必须写出其真正名称、来源、日期和实际含义，并说明它回答的问题与正式指标有何不同。展示辅助指标不改变正式指标的Unavailable状态。已经正式批准的同指标provider优先级或fallback可以使用，但不得跨方法学补数。

### 2.4 MVRV Ratio

长期估值主指标。报告最新可靠数值、区间及历史含义，回答“BTC相对链上成本基础总体偏贵还是偏便宜？”

### 2.5 STH-MVRV

短中期持有人状态指标。说明短期持有人整体浮盈、平衡或浮亏；1.0为关键枢轴。

### 2.6 AHR999

长期定投 / 极端估值辅助指标，不单独作为买卖信号。

取数优先级：

1. AIX4U AHR999 Dataset最新完整日线；
2. 项目GitHub原始JSON / CSV；
3. Hugging Face镜像；
4. 9992100.xyz实时接口仅辅助参考。

必须标注UTC日期或时间、来源、数值、区间，并尽量报告`quantile5y`。

参考区间：

- `ahr999 < 0.45`：历史低估 / 价值区；
- `0.45 ≤ ahr999 < 1.20`：定投区；
- `1.20 ≤ ahr999 < 3.00`：谨慎；
- `ahr999 ≥ 3.00`：泡沫风险。

### 2.7 美国现货BTC ETF Flow

观察机构真实资金。主数据源固定为Farside Investors：`https://farside.co.uk/btc/`。

数据新鲜度与完整性规则：

1. 当前Farside页面优先于搜索摘要、搜索缓存和旧抓取结果；来源冲突时，以当前Farside页面为准。
2. 单个基金单元格中的`-`、空白或缺失均表示未知，绝对不能自动解释为0；只有明确数值0或0.0才视为零流量。
3. 单元格完整性与整个交易日完整性必须分开判断。每个交易日标记为`complete`、`provisional`或`unavailable`。
4. 完整性判断的核心基金为IBIT、FBTC、BITB、ARKB、GBTC、BTC。
5. `Total`可解析且核心基金全部为明确数值（包括明确的0.0）时，该交易日为`complete`。
6. `Total`可解析但存在缺失核心基金时，该交易日为`provisional`；其`Total`不得作为正式日报值或纳入正式累计。
7. `Total`不可解析时，该交易日为`unavailable`。
8. 非核心基金出现`-`、空白或缺失时，不得当作0，必须保留在`missing_funds`；但在核心基金完整且`Total`可解析时，不因此自动否决整行的`complete`状态。
9. 最新页面交易日为`provisional`时，日报主指标使用最近一个`complete`美国交易日；可额外报告最新暂报日期、暂报净流量和缺失基金，并明确该暂报值没有作为正式日流量使用。
10. 只有当前页面不存在任何可靠的`complete`行时，才写“未取得可靠完整值”。
11. 固定报告最近完整交易日总流量、前一个完整交易日总流量、最近3个完整美国交易日累计和最近5个完整美国交易日累计。3D / 5D按`complete`交易日数量计算，不按自然日计算。
12. 最近两个`complete`交易日总流量正负方向相反时，输出`sign_flip = true`；否则为`false`。脚本只输出事实，不自行设置“大额反转”“明显改善”“恶化”等投资阈值。
13. 每次取数必须记录`fetched_at_utc`、`source_url`、`latest_page_date`、`latest_complete_date`、`latest_row_status`，明确区分页面最新日期与正式采用日期。

优先观察完整交易日之间的连续性与多日累计，不以单个缺失单元格、单日噪声或未经确认的暂报值机械下结论。

### 2.8 BTC永续合约Funding

观察杠杆情绪。当前不依赖CoinGlass API Key即可完整运行。

当前CoinGlass网页仅用于人工核对，不作为无人值守自动provider。

数据源与provider规则：

1. 使用多家官方交易所公开API。OKX为正常质量状态和exit 0必须成功的主公开源，Bybit为第二官方源，Binance为best-effort第三源。
2. Binance因HTTP 403、451、地区限制或网络阻断不可用时，标记`unavailable`并保留真实原因，但不得单独导致整个Funding模块失败。
3. 单个平台失败时，允许使用其他可用官方源；正式`reference_funding`按OKX、Bybit、Binance顺序选择首个状态可用且周期可靠的平台。OKX失败但Bybit或Binance可用时，主体仍可输出，但必须warning并进入降级质量状态或exit 2，不得误判为exit 0或直接因Binance失败而exit 1。
4. 每个平台同时保留当前 / 预计Funding与最近实际结算Funding，并记录平台、合约、数据时间、Funding时间、原始rate、原始结算周期、8h equivalent、请求URL、HTTP状态、缓存状态和warning。`unavailable`不得写成0。
5. Funding周期不得默认固定为8小时。必须根据接口明确周期字段、相邻计划结算时间或可靠的连续历史结算间隔确认；周期无法可靠确定时，保留原始数据并warning，`normalized_8h`标记为unavailable，不得擅自假设8h。
6. 周期可靠时，统一计算：`rate_8h_equivalent = raw_rate × 8 ÷ interval_hours`。不得只输出换算值而隐藏原始rate和原始周期。

8小时等效口径的状态区间：

- `<0% / 8h`：`negative`，不属于多头过热；
- `0% ≤ rate < 0.03% / 8h`：`neutral_or_healthy`；
- `0.03% ≤ rate ≤ 0.05% / 8h`：`caution`；
- `>0.05% / 8h`：`overheated`。

若至少两个平台有可比较的8小时等效值，可以输出`min_8h`、`max_8h`、spread、`simple_mean_8h`和正负方向一致性。`simple_mean_8h`只是简单算术平均，不是持仓量加权Funding，不得冒充全市场Funding或CoinGlass OI-weighted Funding。

CoinGlass是未来可选升级，不是当前强制依赖。缺少`COINGLASS_API_KEY`不得产生warning或失败；只有在API Key与接口经过实际验证后，才可增加CoinGlass OI-weighted Funding作为主指标。未来如取得并验证成交额加权Funding，也只能作为交叉验证；现有OKX、Bybit、Binance官方数据必须继续作为交叉验证和fallback。

### 2.9 aSOPR

真实链上已实现盈亏指标。报告最新可靠值，优先同时观察7DMA。

- >1：平均盈利兑现；
- ≈1：盈亏平衡 / 成本重置；
- <1：平均亏损兑现。

不因单日轻微偏离1机械下结论，重点看持续性与7DMA趋势。

### 2.10 SSR Oscillator

观察稳定币相对BTC的潜在购买力。优先使用SSR Oscillator，不用原始SSR绝对值作为主判断。

- 0附近：平衡；
- 负值：稳定币相对购买力更充足；
- 正值：相对购买力减弱；
- ±2附近：统计极端参考，不得机械交易。

### 2.11 CVDD长期底部锚模块（双轨制）

CVDD模块由两个口径和用途互相独立的指标体系组成：

- Track A：BGeometrics CVDD Trend；
- Track B：Glassnode PiT CVDD。

BGeometrics CVDD Trend回答“长期锚本身怎么走”和“BTC相对这个锚正在靠近还是远离”；Glassnode PiT CVDD回答“BTC距离历史极端底部PiT锚还有多远”。两者互补，不是替代关系。

严禁在两套体系之间混算、拼接历史序列、共用未经验证的阈值，或把BGeometrics CVDD标成Glassnode PiT CVDD。也严禁使用其他自建CVDD估算值直接套用Glassnode PiT阈值。

#### 2.11.1 Track A：BGeometrics CVDD Trend数据源与用途

BGeometrics CVDD Trend作为每日CVDD趋势主源。

已实测验证的数据源：

- CVDD：`GET https://api.bitcoin-data.com/v1/cvdd`；
- BTC价格：`GET https://api.bitcoin-data.com/v1/btc-price`。

当前验证结果：HTTP 200、无需API Key、免费额度可用、免费历史约4年、支持历史区间查询。最近40天验证连续，无缺失和重复；历史一年范围内曾发现个别缺失日期，因此不得假设历史数据100%连续。

每次使用必须标注数据源、实际数据日期，以及是否为当日最新可靠值。

#### 2.11.2 BGeometrics CVDD自身趋势

固定展示：

- 当前最新可靠CVDD；
- 30日前CVDD；
- 90日前CVDD。

计算：

- 30D变化率 = 当前CVDD ÷ 30日前CVDD − 1；
- 90D变化率 = 当前CVDD ÷ 90日前CVDD − 1。

趋势判断：

- ↑ 底部锚上移；
- → 基本横盘；
- ↓ 底部锚回落。

重点解释趋势方向和速度，不夸大单日几个美元或几十美元的变化，也不得仅因单日CVDD涨跌给出看多或看空结论。

#### 2.11.3 BGeometrics Price/CVDD

优先使用BGeometrics同源BTC价格：`GET https://api.bitcoin-data.com/v1/btc-price`。

计算：

- Price/CVDD = 同日期BTC Price ÷ 同日期BGeometrics CVDD。

固定展示：

- 当前Price/CVDD；
- 7日前Price/CVDD；
- 30日前Price/CVDD。

可额外展示90日前Price/CVDD，用于辅助判断更长周期方向。

必须计算：

- 7D变化率；
- 30D变化率。

如展示90D，则同时计算90D变化率。

日报分析层可根据变化描述快速接近CVDD、缓慢接近CVDD、距离基本稳定、缓慢远离CVDD或快速远离CVDD；自动取数层只输出数值和方向，不得自行发明“快速 / 缓慢”数值阈值。

BGeometrics Price/CVDD当前数值可能处于4、5、10等数量级。目前只用于趋势和相对变化判断；除非以后基于同一BGeometrics历史序列重新完成历史校准，否则不设置绝对底部阈值。

绝对禁止把Glassnode PiT的1.30、1.15、1.05、1.00监控区间套到BGeometrics Price/CVDD上。

#### 2.11.4 BGeometrics每月365D

每个月第一份日报额外展示：

- 当前CVDD；
- 365日前CVDD；
- 365D变化率。

目的：观察过去一年CVDD长期锚整体抬升速度；无需每天重复。

#### 2.11.5 BGeometrics历史日期缺失与每日质量检查

如果7日前、30日前、90日前、365日前等目标日期没有记录，必须：

1. 向前寻找最近一个有效日期；
2. 明确标注原目标日期和实际使用日期；
3. 不得把缺失值当成0；
4. 不得静默使用错误日期；
5. 如果日期偏差过大，明确提示数据质量问题。

每天还应检查：

- 最新数据实际日期；
- 数据延迟多少日；
- 是否存在重复日期；
- 是否存在异常缺口。

#### 2.11.6 Track B：Glassnode PiT CVDD

Glassnode PiT CVDD继续保留，作为独立的“历史极端底部距离锚”，不承担每日30D / 90D趋势主源职责。

只有在取得可靠PiT CVDD数值、明确对应日期，以及同日期或可靠匹配的BTC价格时，才计算：

- Price/PiT-CVDD = BTC Price ÷ Glassnode PiT CVDD。

每个数据必须明确标注来源和对应日期。普通Glassnode CVDD或其他来源不得冒充Glassnode PiT CVDD。

#### 2.11.7 Glassnode PiT固定监控区间

以下区间只适用于Glassnode PiT CVDD口径：

- >1.30：离历史极端底部仍有明显距离；
- 1.15–1.30：重点观察区；
- 1.05–1.15：历史重要底部区域；
- ≤1.05：极端底部区域；
- ≈1.00：接近或触及PiT CVDD。

这些区间只用于历史监控与预警，不是机械买卖线。

历史校准优先参考2015、2018、2022三个完整周期底部；2020 COVID仅作为极端流动性冲击参考。

如果Glassnode PiT只有缓存值、没有可靠日期或无法匹配BTC同期价格，明确写“Glassnode PiT CVDD：未取得可靠值”。不得用旧值冒充当天值，不得用BGeometrics数值补位，不得用BGeometrics历史序列拼接Glassnode PiT，也不得用BGeometrics Price/CVDD套用PiT阈值。

#### 2.11.8 Bitbo定位

Bitbo当前实测返回HTTP 428并有Cloudflare Turnstile，无法验证无人值守自动获取，因此只保留为人工交叉核对候选，不是已验证的自动备用数据源。

只有在以后实际验证无需登录、无需人工挑战并可稳定自动导出之后，才允许升级为正式备用源。

### 2.12 高价值候选 / 增强指标

#### 2.12.3 Pi Cycle Top

### 2.13 加密结构性要闻

在BTC核心指标之后，正式设置“加密结构性要闻”。每天0～3条，不要求每天必须出现，也不得为凑数降低标准。

只收录核心指标没有覆盖、但可能改变市场中长期判断的事件：

1. **重大安全 / 托管风险**：大型交易所攻击、硬件钱包重大漏洞、稳定币脱锚、系统性协议风险等。
2. **机构 / 市场结构**：大型机构重大资产配置、监管结构变化、托管体系变化、ETF市场结构变化、大型上市公司策略发生实质变化等。
3. **链上金融 / RWA结构趋势**：tokenized equities、tokenized treasuries、stablecoin payment、securities on-chain等真正形成结构性变化的事件。

普通ETF单日流量等已经在核心指标中充分体现的事件，不得再次包装成结构性新闻重复报告。

证据优先级为官方公告、监管文件、SEC或公司披露、高质量研究机构和可靠主流媒体。单个链上分析师、社交媒体帖子、中文转载不得直接作为高影响事实。某鲸鱼转币默认不进入日报；只有金额足够重要、来源可靠且可能影响市场结构时，才考虑加入。

### 2.14 BTC综合判断

不得由单一指标决定BTC结论或总灯号。综合判断应结合长期估值、短期持有人状态、真实兑现行为、稳定币购买力、机构资金、杠杆情绪、CVDD长期底部锚、必要的长期持有人分配风险与宏观环境，并说明主要证据和相反风险。

## 4｜国内外重大新闻

本板块只保留真正可能影响市场、政策、产业、地缘或用户决策的重要新闻，不做普通新闻大全。

与AI、BTC或宏观板块已经充分展开的同一事件不得重复。跨板块事件应确定一个主要归属；其他板块只在确有必要时简短交叉引用。普通社会新闻除非重要性极高，否则不进入日报。

同一底层事件的多个来源、转载或地域角度按一个主题聚类。只有后续出现实质新进展时才再次报告，并明确“新增了什么”。没有达到标准的事件时宁缺毋滥，不用旧闻填充。

## 5｜今日5点总结

日报结尾固定设置“今日5点总结”，原则上4～5条，不要求用重复内容强行凑满5条。

重点回答：

1. 今天最大的变化是什么？
2. 哪个指标或事件最值得盯？
3. 最大风险是什么？
4. 哪个积极信号最值得注意？
5. 什么未来信号会改变当前判断？

该部分属于决策层压缩，不是复述全部正文。每一点应能回指前文证据，不得在总结中新增未经验证的事实或把推测改写成结论。
