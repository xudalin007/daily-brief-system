## 2026-08-02 — v1.1 接力升级

### 灯号体系正式固定
- 在“0｜今日30秒结论”的总灯号表正下方固定放置灯号说明，然后再进入“一、人工智能与科技”。
- 灯号扩展为五档：
  - 🟢绿＝环境/信号总体有利
  - 🟡黄＝中性或多空交织、需观察确认
  - 🟠橙＝风险明显升高、应提高警惕
  - 🔴红＝高风险或明显不利
  - ⚪灰＝数据不足/暂无法可靠判断
- “偏绿/偏橙”等仅表示主灯号内部的方向倾斜，不改变灯号等级。
- ⚪灰不是看空，而是“数据不足，不做判断”。

### AI与科技板块融合去重
- 同一事件、模型、公司或产品若被多个来源重复报道，合并成一个主条目。
- 相关补充信息并入主条目，避免多个小标题重复堆叠同一件事。

### ETF Flow 自动采集修复
- 自动采集优先使用 Farside 数据。
- 当前网络/自动运行环境需要时，可通过 jsDelivr 镜像/分发链路获取 Farside 数据。
- 镜像仅解决可访问性，不改变原始数据口径。
- 缺失/未完整不得写成0。

### Funding 自动采集策略调整
- 因当前自动运行环境存在网络访问限制，日常自动取数优先 Gate.io 可访问公开接口。
- OKX、Binance、Bybit 等在可访问时用于交叉验证或替代。
- 单个平台失败不得导致 Funding 整项缺失。
- 一旦获得可用 CoinGlass API Key，主指标自动升级为 OI 加权 Funding。

### PiT CVDD 历史比较增强
- 除原有30D/90D慢变量外，增加“上一可靠日”和“7日前”的近期历史比较。
- 日/周变化用于观察近期斜率，30D/90D继续用于判断长期底部锚趋势。
- 不得用短期几美元/几十美元变化机械得出多空结论。

### 跨聊天接力
- 对话达到长度上限后，以 `daily_brief_rules.md` + `daily_brief_changelog.md` + 最新 `checkpoint_YYYY-MM.md` 三件套恢复。
- 新聊天中“今天日报”继续作为同一套日报系统的手动触发词。

## 2026-08-02 — Update daily brief reporting framework

原规则：

- 日报固定覆盖AI与科技、BTC与加密、宏观经济与投资、国内外重大新闻，但没有正式定义总览层、证据层和结论层，也没有固定开头与结尾的决策压缩结构。
- 事件筛选主要强调最近24小时和避免信息堆砌，尚未固定AI的7天重大补漏、来源等级、事件聚类、主题数量与跨板块去重规则。
- BTC指标已有各自业务口径，但尚未建立统一仪表盘和`Verified / Delayed / Provisional / Unavailable`数据质量状态，也未全面禁止相关指标冒充正式指标。
- 综合判断仅使用绿、黄、橙、红四级灯号，尚未定义灰灯、偏绿 / 偏橙语义和灯号说明的固定位置。

新规则：

1. 日报正式采用“总览层—证据层—结论层”三层架构，并固定为“0｜今日30秒结论、1｜人工智能与科技、2｜BTC与加密市场、3｜宏观经济与投资、4｜国内外重大新闻、5｜今日5点总结”。
2. 开头固定提供今日最重要的一句话和BTC、AI、宏观及必要时能源 / 地缘总灯号；灯号扩展为绿、黄、橙、红、灰五级，并明确偏绿 / 偏橙不改变主等级、灰灯只代表数据不足。
3. AI采用“24小时核心扫描 + 7天重大事件补漏”，固定Level 1至Level 4来源等级；高影响事实优先由官方一级源或可靠主流媒体验证。
4. AI按事件 / 主题聚类和去重，原则上每天输出4～5个高价值主题，宁缺毋滥；每个主题区分事实、为什么重要、产业 / 投资影响以及推测或待验证内容。
5. BTC板块先展示核心指标仪表盘，统一标注最新值、趋势、信号、数据日期和`Verified / Delayed / Provisional / Unavailable`数据质量；正文只重点展开约3～4项当天变化最大且最值得解释的指标。
6. 正式禁止Long-Short Diff冒充STH-MVRV、Network Profit/Loss冒充aSOPR，以及其他相关指标借用正式指标名称；正式指标不可用时必须保留Unavailable或“未取得可靠值”。
7. CVDD继续严格执行BGeometrics趋势与Glassnode PiT极端底部距离双轨制，不同口径不得混算、拼接或共用PiT阈值。
8. ETF既有完整性、暂报回退、完整交易日3D / 5D累计和`sign_flip`规则继续有效；Funding继续保留多官方交易所、实际周期、原始rate、8h equivalent和可选CoinGlass升级，并明确OKX是exit 0条件、其他官方源可降级输出、简单平均不是OI-weighted Funding。
9. BTC核心指标后新增“加密结构性要闻”，每日0～3条，仅收录安全 / 托管、机构 / 市场结构和链上金融 / RWA等有中长期增量影响且证据可靠的事件。
10. 宏观板块原则上筛选约3～4个关键事件，并固定加入投资影响矩阵，展示对BTC、黄金、美股科技和A股的当前传导方向；矩阵不是确定价格预测，不得把相关性直接写成确定因果。
11. 国内外重大新闻进一步执行事件聚类和跨板块去重；AI、BTC或宏观已充分展开的同一事件不得重复。
12. 结尾固定“今日5点总结”，原则上用4～5条压缩当天最大变化、最值得关注的信号、最大风险、积极因素和可能改变判断的后续信号。
13. 日报长度正式遵循“更全面不等于更长”，通过表格化、聚类、去重和重点展开提高完整度与可读性，同时保持严格的数据可靠性、日期一致性、指标口径和来源验证。
14. 消除既有AHR999区间在精确`3.00`处的文字歧义：`1.20 ≤ ahr999 < 3.00`为谨慎区，`ahr999 ≥ 3.00`为泡沫风险区，与已验收自动模块保持一致，不改变原有阈值位置。

修改原因：

- 最近的ChatGPT日报测试已正式确认，新结构能让读者先快速理解当日变化，再核对证据，最后得到可执行的观察结论。
- 通过固定证据等级、数据质量状态、事件聚类和跨板块去重，减少标题驱动、旧闻填充、重复叙述及不可靠指标替代。
- 在不改变既有核心BTC指标业务口径的前提下，提升日报的信息密度、决策价值和长期一致性。

## 2026-08-01 — CVDD升级为双轨数据体系

原方案：

- 主要依赖Glassnode PiT CVDD同时承担趋势与底部距离判断，但公开历史数据获取不稳定。

新方案：

1. BGeometrics CVDD成为每日趋势主源。
2. 使用同源 `btc-price` 计算BGeometrics Price/CVDD。
3. 固定展示CVDD 30D/90D趋势，每月第一份日报增加365D。
4. Price/CVDD固定展示7D/30D趋势，可额外展示90D。
5. Glassnode PiT独立保留为历史极端底部距离锚。
6. 原有1.30、1.15、1.05、1.00监控区间只适用于Glassnode PiT口径。
7. BGeometrics与Glassnode PiT两套数据禁止混算、拼接历史序列或共用未经验证的阈值。
8. 目标日期缺失时向前寻找最近有效日，并明确标注原目标日期和实际使用日期。
9. Bitbo暂不作为自动备用源，只保留为人工交叉核对候选。

修改目的：

- 解决Glassnode PiT公开历史序列无法稳定获得的问题，同时保留PiT历史极端底部判断价值，并建立可稳定每日计算的CVDD趋势体系。

## 2026-08-01 — Refine ETF Flow freshness and completeness rules

原规则：

- 报告最近完整美国交易日数据；当天数据不完整时标注；缺失不得写成0；优先观察连续性与多日累计。
- 未明确单个基金缺失与整日完整性的区别，也未固定核心基金、交易日状态、暂报回退、累计窗口和新鲜度字段。

新规则：

1. Farside Investors `https://farside.co.uk/btc/` 固定为主源；当前页面与搜索摘要、搜索缓存或旧抓取结果冲突时，以当前页面为准。
2. `-`、空白和缺失单元格永远不等于0；单个次要基金缺失不自动否决整日完整性。
3. 以 IBIT、FBTC、BITB、ARKB、GBTC、BTC 六个核心基金及可解析的 `Total` 判断交易日状态：核心基金完整时为 `complete`，核心基金缺失时为 `provisional`，`Total` 不可解析时为 `unavailable`。
4. 最新交易日为 `provisional` 时，正式日报回退到最近 `complete` 日，并可另行提示暂报总额与缺失基金；没有可靠 `complete` 日时写“未取得可靠完整值”。
5. 正式比较和累计只使用 `complete` 交易日：记录最近完整日、前一完整日、最近3个和5个完整交易日累计，以及连续完整日的 `sign_flip`；不增加投资阈值。
6. 固定记录 `fetched_at_utc`、`source_url`、`latest_page_date`、`latest_complete_date`、`latest_row_status`。

修改原因：

- 此前日报曾因旧缓存错过7月31日的 `-265.4M`，因此必须优先核对当前 Farside 页面并明确区分页面最新日期与正式采用日期。
- 进一步验证发现，Farside 历史最终数据也可能包含单个基金的 `-`；因此不能使用“有 `-` = 整日不完整”的过度简单规则，必须区分单元格完整性与交易日完整性。

## 2026-07-30 — CVDD模块升级

原方案主要展示最新 PiT CVDD、当前 Price/CVDD 和固定阈值。

正式升级为：
- PiT CVDD：当前、30日前、90日前；计算30D/90D变化率；判断底部锚上移/横盘/回落。
- Price/CVDD：当前、7日前、30日前；计算7D/30D变化率；判断快速接近/缓慢接近/稳定/缓慢远离/快速远离CVDD。

- 强制标注数据来源及日期/时间。
- 缓存、延迟或日期无法确认的数据不得称为“今日最新”。
- 普通 Glassnode CVDD、Bitbo仅作交叉核对，不与PiT CVDD混用历史阈值。

升级目的：同时回答“长期底部锚自己怎么走”和“BTC离底部锚越来越近还是越来越远”。
